# Chain 2048 minigame — root causes and fixes

## Architecture (how the game works)

- **Authority:** The full game state (4×4 board, score, win flag, session status) lives in **`Game2048Session`** on the server. The client does not simulate merges locally for persistence; it sends **`POST /games/2048/move`** with `{ sessionId, direction }`.
- **Engine:** `server/services/game2048Engine.js` implements classic 2048 rules: `moveBoard`, `mergeLineTowardZero` (single merge pass per line — no double-merge in one move), `spawnRandomTile`, `hasValidMove`, `maxTile`, `parseBoard`.
- **Service:** `server/services/game2048Service.js` applies moves inside a transaction, updates score (`scoreDelta` from merges), spawns a new tile after each successful move, ends the round when there are no legal moves or when the time limit elapses.
- **Client:** `client/src/pages/Game2048Page.jsx` renders the board from `session.board`, shows score from `session.score`, progress from the highest tile vs `winTile`, and wires keyboard + touch swipes to `sendMove`.

## Root causes of the reported bugs

### 1. Score / grid felt “stuck” (state and input)

The client **blocked every move** when the round timer showed `0` seconds:

```text
if ((session.timeLimitSeconds ?? 0) > 0 && roundSeconds === 0) return;
```

The timer was computed only from `startedAt` + `timeLimitSeconds` on the client (`Date.now()`). The server still used **`createdAt`** + the same limit. Any **clock skew** (client ahead of the server, or drift between ticks) could make **`roundSeconds === 0` while the session was still `ACTIVE` on the server**. Result: API was still valid, but the UI refused to send moves — score and board appeared frozen.

**Fix:** Remove that client-side hard stop. Timeouts remain **server-authoritative** (`finalizeTimedOutSession` + `secondsRemaining` in API responses).

### 2. Progress bar stuck at 0%

Progress uses the **highest tile** on the board vs `winTile`. The UI used:

```text
Math.max(...board.flat())
```

For an **empty** or **non-rectangular** board, `Math.max(...[])` is **`-Infinity`**, which broke the progress formula and showed **0%**.

**Fix:** `bestTileOnBoard()` in `client/src/games/game2048BoardUtils.js` safely scans cells and never spreads an empty list.

### 3. Board / score desync from JSON

`parseBoard` only accepted **number** cells. Some JSON paths can deserialize numeric tiles as **strings**. Parsing failed → service fell back to an **empty board** in serialization while the DB still held data — confusing UI and zero progress.

**Fix:** `normalize2048Cell()` + relaxed `parseBoard` accept integer strings (e.g. `"128"`).

## Reward integration (unchanged rules, clarified)

- **`won`:** Set when `maxTile(board) >= winTile` (default 2048 from env).
- **`canClaim` (API):** `won && score >= minScore && !rewardGranted && status !== CLAIMED`.
- **Claim:** `POST /games/2048/claim` creates `UserPowerGame`, marks session claimed, applies cooldown from constants. Still **once per successful claim**; idempotent response if already granted.

## Logging added

Structured logs under the **`Game2048`** logger child:

| Event | Level | When |
|-------|-------|------|
| `game2048_move_noop` | debug | Valid move request but grid did not change |
| `game2048_move_applied` | info | Move applied; includes `scoreDelta`, `scoreAfter`, `maxTileAfter` |
| `game2048_board_parse_failed` | warn | Stored JSON could not be parsed to a 4×4 integer grid |
| `game2048_reward_claimed` | info | Reward granted and session marked claimed |

## Before vs after

| Symptom | Before | After |
|---------|--------|--------|
| Moves near end of timer | Often blocked on client | Always sent; server decides |
| Progress bar | Could stay at 0% | Stable percentage from best tile |
| String tile values in JSON | Parse fail → empty UI board | Parsed as integers |
| Score label | Rare string from JSON | Coerced with `Number()` for display |

## Game rules implemented

- 4×4 grid; two initial tiles on start / restart.
- On each key direction: slide + merge **once** per line toward that edge; then spawn one new 2 (90%) or 4 (10%) on a random empty cell **only if** the board changed.
- Score increases by the **value of each merged pair** (sum of new tiles created from merges).
- Round ends when no moves exist or time limit exceeded (if enabled); win flag when `maxTile >= winTile`.
